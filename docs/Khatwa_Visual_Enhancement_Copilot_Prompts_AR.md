# Khatwa Designs — Visual Enhancement with GitHub Copilot

## الهدف

إضافة عمق بصري وحركة متوسطة إلى موقع Khatwa Designs الحالي، مستوحاة من التدرجات والإضاءات في موقع ME-2026، مع الحفاظ على هوية خطوة، والمحتوى الحالي، وروابط الصفحات، والاستجابة للموبايل، وإتاحة الوصول.

### الاتجاه البصري المعتمد

- مزيج من **Premium Gradients + Engineering-Inspired Details** مع بعض الأشكال العائمة المحدودة.
- مستوى الحركة: متوسط، ناعم وغير مشتت.
- مناطق التركيز: Hero، بطاقات الخدمات، الأعمال المختارة، وقسم طلب عرض السعر.
- ألوان الهوية الحالية التي يجب الحفاظ عليها:
  - Navy: `#1C3664`
  - Yellow: `#FFCD05`
  - Gray: `#CCCCCB`
- يسمح باستخدام درجات مشتقة من ألوان الهوية في التدرجات، مع الأبيض ومساحات محايدة. لا تضف لوحة ألوان مستقلة.

## تعليمات عامة لـ Copilot

1. افحص الملفات الفعلية قبل تعديلها، ولا تفترض أن أسماء الأقسام أو selectors مطابقة للأسماء في هذه الوثيقة.
2. لا تعِد بناء الموقع من الصفر، ولا تغيّر المحتوى أو الترجمة أو مسارات الصفحات أو بنية التنقل.
3. ابدأ بمراجعة `git status --short` و`git diff`. احتفظ بكل التعديلات الموجودة، ولا تستخدم أوامر حذف أو reset.
4. اجعل التغييرات الخاصة بالهوية في `corporate.css` أساسًا. عدّل HTML فقط لإضافة classes أو عناصر زخرفية ضرورية وبسيطة، وعدّل JavaScript فقط إذا كان هناك سبب واضح لا يمكن تحقيقه بـ CSS.
5. لا تضف مكتبات أو dependencies جديدة للحركة. استخدم CSS transitions/animations، وIntersectionObserver فقط إن لم يكن المشروع يملك أصلًا نظام reveal مناسبًا.
6. لا تستخدم صور stock بديلة في المحتوى الحقيقي ولا تخترع أعمالًا أو أرقامًا أو testimonials.
7. لا تعدّل `contact.html` أو `main.js` أو أي منطق خاص بإرسال النماذج أو EmailJS. الاختلاف السابق في تقرير الفحص يجب أن يُحسم منفصلًا؛ هذه المهمة بصرية فقط.
8. حافظ على RTL وLTR، العربية والإنجليزية، لوحة المفاتيح، hover/focus، وسلوك الموبايل.
9. احترم `prefers-reduced-motion: reduce`: عطّل الحركة المستمرة والانتقالات غير الضرورية أو قلّلها بوضوح.
10. لا تجعل الحركة ضرورية لفهم النص، ولا تخفِ المحتوى قبل تشغيل JavaScript، ولا تسبب layout shift.
11. تجنّب تحريك خصائص مكلفة مثل `top/left/width/height` باستمرار. استخدم `transform` و`opacity` حيثما أمكن.
12. بعد التنفيذ، أبلغني بوضوح عن الملفات المتغيرة، وما الذي تغيّر، وما الاختبارات التي نجحت أو تعذّر تشغيلها. لا تنشر الموقع.

# المرحلة 0 — تدقيق بصري فقط (لا تعدّل)

انسخ هذا الأمر إلى Copilot Chat:

```text
نفّذ تدقيقًا بصريًا وتقنيًا لموقع Khatwa Designs دون تعديل أي ملف.

راجع:
- index.html
- corporate.css
- responsive.css
- style.css عند الحاجة فقط
- khatwa-layout.js إذا لزم فهم الهيدر والفوتر
- أي JavaScript حالي مسؤول عن reveal أو animation أو sliders.

افحص حالة Git أولًا. ثم حدد بدقة:
1. العنصر الحالي الذي يمثل Hero وselectors الخاصة به.
2. selectors بطاقات الخدمات والأعمال وقسم طلب عرض السعر.
3. الخلفيات الحالية لكل من الأقسام الأربعة، وألوانها، وما إذا كان هناك gradient أو pseudo-element مستخدم أصلًا.
4. قواعد responsive ذات الصلة للموبايل.
5. هل هناك مكتبة أو وظيفة motion/reveal مستخدمة بالفعل؟ لا تضف واحدة بديلة قبل التحقق.
6. ما أقل مجموعة ملفات تحتاج إلى التعديل.

أخرج جدولًا: المنطقة | selectors الحالية | التعديل البصري المقترح | الملفات المتوقع تعديلها | مخاطر التوافق.
لا تعدل الملفات، ولا تثبّت حزمًا، ولا تغيّر المحتوى أو الترجمات أو النماذج.
```

**شرط الانتقال:** اقرأ التقرير وتأكد أن Copilot ربط الاقتراحات بالـ selectors الفعلية للموقع، لا بأسماء افتراضية.

# المرحلة 1 — Hero: التدرجات والإضاءة

```text
نفّذ الآن تحسين Hero فقط على موقع Khatwa Designs، اعتمادًا على التدقيق السابق.

التوجه:
- خلفية متعددة الطبقات بتدرج كحلي/أزرق مبني على #1C3664.
- إضاءة radial ناعمة جدًا بدرجات مشتقة من الأزرق، ويمكن إضافة لمسة صفراء #FFCD05 بشفافية منخفضة في موضع محدود.
- إضافة texture هندسي خفيف جدًا (شبكة أو خطوط دقيقة) عبر CSS إذا أمكن، بحيث يكون زخرفيًا فقط ولا يقلل وضوح النص.
- حركة بطيئة وناعمة للإضاءة/الطبقة الزخرفية، وليست حركة قوية أو وميضًا.
- حافظ على وضوح عنوان Hero، النص، الأزرار والتباين.
- لا تحرك أو تغيّر محتوى النص، ولا تغيّر ارتفاع Hero أو تخطيطه إلا عند وجود ضرورة مثبتة.
- لا تضف صورًا خارجية أو مكتبات.
- تأكد من وجود بديل ساكن جميل عندما تكون الحركة معطلة أو على الأجهزة الصغيرة.
- احترم prefers-reduced-motion.

عدّل أصغر عدد ممكن من الملفات، وفضّل corporate.css. بعد التعديل، اعرض diff واذكر selectors التي استهدفتها. لا تنتقل إلى الأقسام الأخرى في هذه المرحلة.
```

**معيار القبول:** Hero جذاب بصريًا، لا يوجد تباين ضعيف أو قص للمحتوى أو وميض، والأزرار والنصوص مقروءة على الشاشات الصغيرة والكبيرة.

# المرحلة 2 — بطاقات الخدمات والأعمال

```text
حسّن التفاعل البصري لبطاقات الخدمات والأعمال المختارة فقط.

المطلوب:
1. بطاقات الخدمات: transition ناعم عند hover/focus، ارتفاع بسيط جدًا عبر transform، وظل متزن وحد/لمعة خفيفة مستمدة من ألوان الهوية. لا تستخدم scale كبيرًا ولا حركة متكررة.
2. بطاقات الأعمال: تكبير الصورة بشكل طفيف داخل حدود overflow المخطط لها، مع انتقال سلس، وإبراز اسم المشروع ورابطه عند hover/focus مع إبقاء الاسم والرابط واضحين على الموبايل حيث لا يوجد hover.
3. احتفظ بأبعاد الصور وتناسبها ومواقع الروابط الحالية.
4. طبّق حالات keyboard focus بشكل واضح، وتأكد أن hover ليس الوسيلة الوحيدة لإظهار أي معلومات مهمة.
5. أضف قواعد responsive عند الحاجة فقط، وتجنب تغييرات markup واسعة.
6. احترم prefers-reduced-motion.

لا تعدّل النصوص أو روابط Behance أو الأصول أو النماذج. أظهر diff واكتب checklist قصيرة لما اختُبر.
```

**معيار القبول:** الحركة ملحوظة لكن هادئة، ولا يحدث قفز في ارتفاع البطاقات، ولا تنقص إمكانية الضغط أو قراءة معلومات المشاريع.

# المرحلة 3 — قسم طلب عرض السعر (CTA)

```text
حسّن الخلفية البصرية لقسم طلب عرض السعر الختامي فقط.

استخدم خلفية كحلية/زرقاء متدرجة، مع إضاءة ناعمة في أحد الأطراف أو خلفية هندسية خافتة. استخدم الأصفر #FFCD05 لتأكيد بصري محدود على زر الإجراء أو التفاصيل الموجودة أصلًا، ولا تغير نص الزر أو سلوكه.

أضف حركة بطيئة جدًا لخلفية الإضاءة فقط عند ملاءمتها، مع بديل ساكن واحترام prefers-reduced-motion.
حافظ على وضوح النصوص وتباين الزر. لا تعدّل EmailJS أو contact.html أو منطق النماذج.
اعرض diff واذكر قواعد التباين/الموبايل التي راجعتها.
```

# المرحلة 4 — ظهور العناصر أثناء التمرير (اختياري بعد مراجعة المراحل السابقة)

```text
افحص أولًا إن كان الموقع يستخدم بالفعل مكتبة أو كودًا لظهور العناصر أثناء التمرير. إذا كان هناك حل قائم ومستقر، فوسّعه بدل إضافة نظام آخر.

إذا لم يوجد نظام مناسب، أضف reveal خفيفًا ومتدرجًا لعناصر مختارة في Hero (إن كان مناسبًا)، بطاقات الخدمات، بطاقات الأعمال، وCTA فقط:
- انتقال قصير نسبيًا بالـ opacity وtranslateY صغير.
- لا تستخدم stagger طويلًا ولا تؤخر ظهور النص المهم.
- يجب أن يكون المحتوى ظاهرًا افتراضيًا إذا لم يعمل JavaScript أو لم يُفعّل.
- استخدم IntersectionObserver فقط إذا كانت الحاجة حقيقية، مع فصل الكود في ملف مناسب وعدم المساس بمنطق النماذج أو اللغات.
- طبّق prefers-reduced-motion وراقب layout shift.
- لا تطبق reveal على كل عناصر الموقع أو كل فقرة.

اختبر التحميل مع JavaScript، وبدونه إن أمكن، وعند تقليل الحركة. اعرض الملفات والتغييرات والقيود المعروفة.
```

# المرحلة 5 — اختبار نهائي

```text
راجع التعديلات البصرية السابقة دون إضافة تأثيرات جديدة.

نفّذ ما يلي:
1. git diff --check
2. npm run build
3. راجع الأخطاء والتحذيرات الناتجة.
4. اختبر الرئيسية على عرض 1440px و1024px و390px إذا أمكن عبر أدوات المعاينة المتاحة.
5. افحص Hero وبطاقات الخدمات والأعمال وCTA في العربية والإنجليزية.
6. تأكد من RTL/LTR، الروابط، وضوح focus بالكيبورد، وتباين النصوص والأزرار.
7. تحقق من prefers-reduced-motion ومن عدم وجود overflow أفقي أو layout shift واضح.
8. تأكد أن محتوى الصفحات وروابطها ومنطق النماذج لم يتغير.

لا تنشر الموقع ولا تنشئ commit. أعطني تقريرًا بالاختبارات التي نجحت والفاشلة وأسماء الملفات التي تغيرت، مع أي ملاحظات لا يمكن التحقق منها داخل بيئة التطوير.
```

## حدود هذه التعليمات

هذا الملف لا يفترض أن ملفات الموقع أو CSS قد فُحصت مباشرة من داخله، ولا يفترض أن الـ selectors بأسماء معينة. يجب على Copilot مطابقة الأسماء الفعلية في المستودع قبل التنفيذ. كما لا يتضمن أي تعليمات لإعادة إنشاء EmailJS أو تعديل بياناته.
